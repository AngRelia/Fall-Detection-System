- `Core/Src/main.c`

### 2.2 修正陀螺积分步长（最关键，直接决定"准不准"）

> ⚠️ **本节有过一次返工，记录在此以免重蹈覆辙。**

**第一次尝试（错误）**：把融合留在主循环，TIM2（1 kHz）只置 `imu_sample_pending = 1`，
主循环"每次只消耗一个样本"。

**为什么错**：标志只能表示「有过新样本」，**无法表示积压了几个**。主循环频率远低于 1 kHz
（`MMC5603_ReadData_Single` 内含 10 ms 阻塞、OLED 整屏刷新、串口 DMA 等都会拖慢它），
于是每 1 次融合之间实际漏掉了好几个采样。结果是**积分出来的角度严重偏小**——
实测转 90° 只积分出约 10°，同时上电 Yaw 还有一个几十度的虚假偏置。

**最终做法（正确）**：**融合放进 TIM2 中断里**，一个节拍恰好消耗一个样本，一个都不丢。

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        if (fusion_ready)          /* 上电校准+AHRS初始化完成前不融合 */
        {
            Fusion_Task();         /* 每 5ms 精确执行一次 */
        }
    }
    else if (htim->Instance == TIM3) { Key_Tick(); }
}
```

中断不会被 OLED / 串口 / 磁力计阻塞，所以节拍是**真的固定**，`dt` 与
`Mahony_Init()` 的 `invSampleFreq` 严格对应。

**同时把三方节拍统一到 200 Hz**（原来的 1 kHz 融合在 F103 上太吃 CPU）：

| 位置 | 值 | 依据 |
|---|---|---|
| `tim.c` TIM2 | `PSC=719, ARR=499` | 72 MHz / 720 = 100 kHz；100 kHz / 500 = **200 Hz（5 ms）** |
| `main.c` `Mahony_Init()` | `200.0f` | `invSampleFreq = 1/200` |
| `icm42688_driver.c` | `GYRO_CONFIG0 = 0x07`、`ACCEL_CONFIG0 = 0x07` | 手册 bit3:0 = 0x7 → **200 Hz ODR** |

> 这三处**必须同时改**，任意一处不一致，角度就会按比例偏大或偏小。
> 量程不变（陀螺 ±2000 dps、加速度 ±16 g）。
>
> 降低到 200 Hz 的收益：ISR 占空比从约 85% 降到约 17%，同时加速度计与陀螺
> 各自 1 kHz 内部滤波的混叠也被抑制（UI 滤波器截止 100 Hz，200 Hz 采样足够）。

**副产品**：`volatile uint8_t imu_update_count` 的 256 ms 溢出与中断/主循环非原子
读改写竞态一并消除；`yaw_offset` / `yaw_display` 两个只被注释引用的死变量已删除。

**新增就绪门控** `fusion_ready`：上电流程严格为
`校准 → 磁力计(可选) → MahonyAHRSinit → fusion_ready = 1 → 开定时器`，
避免中断在四元数与零偏未就绪时就用错的数据开始融合。

### 2.3 加速度计零偏校准（原来是空操作）

**问题**：`acc_offset_x/y/z` 默认全 0 且从不更新，`IMU_Calibrate()` **只标定陀螺**。
加速度零偏是**系统性**误差，会直接污染 `pitch = atan2(-ax, az)`、`roll = atan2(ay, az)`，
并在 Mahony 里被当成真实重力持续拉偏姿态。

**改法**（`MDK-ARM/icode/icm42688_driver.c`）：

- `IMU_Calibrate()` 现在**同时**标定陀螺零偏与加速度零偏。
- 竖直轴由新宏 `ACC_CALIB_REF_AXIS`（默认 **2 = Z**）指定，另两轴按 0 g 处理。
- **自动判别装配方向**：分别按 +1g / −1g 计算，取偏差较小者，因此丝印面朝上或朝下都适用。
- 新增 `float imu_calib_residual`：三轴残差之和（理想接近 0）。若明显偏大，说明上电时没水平静止放。
- 采样前先把零偏清零，避免重复校准时刻度互相抵消。

### 2.4 六轴一次 burst 读回（消除采样间偏斜）

**问题**：原来 `Get_Acc_ICM42688()` 与 `Get_Gyro_ICM42688()` 各做一次独立 SPI 事务
（两次 CS 拉低/拉高），加速度与陀螺来自**不同采样点**。跌倒检测依赖"自由落体 + 冲击 + 旋转"
的时间对应关系，这个偏斜会削弱判据。

**改法**：新增 `Get_AccGyro_ICM42688()`，**一次读 12 字节**（`0x1F..0x2A`，
手册中这段连续且标注为 `SYNCR` 同步读），同时取回加速度与陀螺并统一扣除零偏。
原有两个单功能函数保留为兼容包装（内部注明会产生偏斜）。

### 2.5 调用 `MahonyAHRSinit()`（原来从未被调用）

原来四元数从 `(1,0,0,0)` 起步、靠 Kp 慢慢收敛，上电头几秒姿态不可信。
现在在静止校准之后调用 `MahonyAHRSinit()`，用一次静止测量初始化姿态。
（六轴模式下传入磁力计分量为 0，函数内部会走 `init_yaw = 0` 分支。）

### 2.9 关于「上电显示 44°」的追查结论

**先说结论：六轴模式下上电 Yaw 在数学上必然是 0°，44° 不是初始化造成的。**

已用数值方法验证 `MahonyAHRSinit()` 的代数（`init_yaw = 0` 分支）：对水平、前倾 30°、
右滚 30°、任意倾斜四种姿态，算出的 `q3`（决定 Yaw 的分量）恒为 `0.0`，Yaw 输出恒为 `0.000°`。
所以初值不可能给出 44°。

那么 44° 只可能来自以下两者之一：

**(1) 陀螺 Z 残余零偏的积分累积。** 六轴模式下 Yaw **没有任何绝对基准**——
加速度计只能观测重力方向（Roll/Pitch），磁力计关闭后 Yaw 完全不可观测，
`MahonyAHRSupdateIMU` 的重力修正项**不改变 Yaw**。已仿真确认：Yaw 的漂移速度
**精确等于**陀螺 Z 零偏。想在上电后某个时刻看到 44°：

| 陀螺 Z 残余零偏 | 达到 44° 所需时间 |
|---|---|
| 0.05 dps | ≈ 880 s（15 分钟） |
| 0.1 dps | ≈ 440 s |
| 0.2 dps | ≈ 220 s |
| 0.44 dps | ≈ 100 s |

**(2) 磁力计实际处于开启状态（九轴）。** 此时 Yaw 被锁到**磁航向**，上电就显示
「板子相对磁北的朝向」。44° 是完全正常的数值，**不是误差**。
注意 `mag_enabled` 的状态会写回 Flash，所以**一旦按过短按切到九轴，之后每次上电都是九轴**。

**判断方法**：上电时看第 4 行提示——
`Mag: ON ` = 九轴（Yaw 是磁航向，44° 正常）；`Mag: OFF` = 六轴。

**修了一个相关的真 bug**：`MahonyAHRSupdateIMU()`（六轴路径）**漏了 `anglesComputed = 0;`**
（只有 `Mahony_update()` 里有，共 2 处）。后果是六轴下 `anglesComputed` 永远停在 1，
使 `getRoll()/getPitch()/getYaw()` 的惰性重算失效、返回陈旧角度。
`Fusion_Task` 是直接调用 `Mahony_computeAngles()` 的，所以显示的角度本身不受影响，
但这个坑已补上。

**同时给磁力计有效性加了保护**：原判据只要求 `mx/my/mz` 三个分量都非 0，
磁力计读失败或强磁干扰时会用**错误的磁航向**去初始化 Yaw。现在要求
`mx²+my²+mz² > 0.01` 才认为有效。

### 2.10 新增诊断页（第 3 页，按键切到 page_index == 2）

六轴模式下原来那一页显示磁力计原始值，没什么用。现在六轴时改为显示融合诊断：

| 字段 | 含义 |
|---|---|
| `GZ` | **当前陀螺 Z 轴零偏（dps）**。静止时 Yaw 的漂移速度就等于它 |
| `RES` | 上电加速度计校准残差（g），正常应 < 0.02 |
| `ST` | `OK` = 上电校准时确实静止；`BAD` = 校准时动了，零偏不可信 |

九轴时该页仍显示磁力计原始值（`MX/MY/MZ`）。

> 这个 `GZ` 就是排查 Yaw 漂移的关键读数：**静止放几分钟，看它是否稳定在 0 附近**。

**⚠️ `RES` 曾恒显示 1.000 —— 那是本指标的公式写错了，不是校准错了。**

`acc_offset_x/y/z` 存的是**修正量**，满足 `正确值 = 读数 − 修正量`。原来的写法是：

```c
imu_calib_residual = |ax_ref - acc_offset_x| + |ay_ref - acc_offset_y| + |az_ref - acc_offset_z|;
```

对竖直轴，`az_ref ≈ +1g`、`acc_offset_z ≈ 0`，所以这一项恒等于 `1g` —— `RES` 永远是 1.000。
根因是**把「修正量」当成了「修正后的值」**。

已改为按轴分别计算：水平两轴修正后应为 0 g（残差 = `abs(mean)`），
竖直轴修正后应为 ±1 g（残差 = `abs(abs(mean - offset) - 1)`）。

新指标经数值验证：

| 场景 | RES |
|---|---|
| 理想平放 | **0.02** |
| 有零偏 + 轻微倾斜 | 0.13 |
| 倾斜 30°（没放平） | 0.50 |
| 校准时晃动了 | 0.35 |

因此 `RES < 0.02` → `ST = OK` 的判据是有效的。

### 2.11 静止自动零偏修正（Gyro Auto-Zero）——解决 Yaw 漂移

**实测数据（本板）**：静止放桌上 `GZ = 0.113 dps`、`RES = 0.043`、**上电 Yaw = 0°**。

上电是 0° 说明初值没问题（与 §2.9 的数值验证一致），**44° 完全是漂移累积**：

    Yaw 漂移速度 = 陀螺 Z 残余零偏 = 0.113 dps = 6.8 °/min
    44° / 6.8 °/min ≈ 6.5 分钟

即上电后放约 6 分半就爬到 44°。这正是六轴方案的固有弱点：
加速度计只能观测重力方向（约束 Roll/Pitch），**不约束航向**，
所以 Yaw 的漂移速度精确等于陀螺 Z 零偏。

**上电那次静态标定（1 秒、500 样本）残留了 0.113 dps** —— 受上电倾斜、温度、噪声影响，
单次标定很难做到 0.01 dps 量级。`RES = 0.043` 也印证了当时板子有约 2.5° 倾斜。

**做法（可穿戴设备的标准手段）**：新增 `GyroAutoZero_Task()`，在主循环里调用。

| 项 | 值 | 说明 |
|---|---|---|
| 静止判据 | 三轴 \|gyro\| < 0.5 dps 且 \| \|a\| − 1g \| < 0.08 g | 足够宽，正常手持晃动会判为运动 |
| 采样节拍 | 每 100 ms 一个样本 | 用 `HAL_GetTick()` |
| 更新周期 | 连续静止 5 秒（50 样本）更新一次 | 均值噪声 ≈ 0.028/√50 = **0.004 dps** |
| 更新方式 | `gyro_offset += 读数均值` | 驱动层读取时已 `-= gyro_offset`，补进去后静止读数收敛到 0 |

**安全性**：
- 必须**连续静止 5 秒**才更新；一旦判定运动（剧烈转动/晃动）立刻清零重来，
  **不会把真实转动学成零偏**；
- 5 秒窗口内发生一次运动就会重新计数，所以正常佩戴走动不会误学；
- 由 `fusion_ready` 门控，上电校准与 `MahonyAHRSinit` 完成前不动作。

**注意事项**：
- 剧烈碰撞若恰好落在静止窗口内，会被当成零偏学掉一小部分。因为窗口是 5 秒、
  且更新量是均值，单次冲击影响很小；若担心可把窗口加长（提高 `n_samples >= 50`）。
- 温度漂移会持续被跟踪（只要设备有静止时段），这对可穿戴是优点。

**诊断页新增 `AZ` 指示**（第 3 页第 4 行）：`AZ:0` 表示还没学到，`AZ:1` 表示已学习。
预期表现：上电静止约 5 秒后 `AZ` 变 `1`，此时 `GZ` 应回落到 **±0.01 dps** 以内，

## 4. 上板验证清单（建议按顺序）

**A. 六轴精度**
1. 水平静止上电 → OLED 第 0 页 Roll/Pitch 应 ≈ 0°，噪声峰峰值 < 0.3°。
2. 抬起前缘倾斜 30° → Pitch ≈ ±30°（**注意符号**，这同时验证了轴向正负）。
3. 向右滚转 30° → Roll ≈ ±30°。
4. 绕板子竖轴**慢速**转 180° → Yaw ≈ 180°，误差 < 5°。
   （这一条能过，说明 §2.2 的 dt 问题确实修好了；改之前这里会明显偏大或超调。）

**B. 加速度零偏校准是否生效**
- 串口打开时看 `imu_calib_residual`。**正常应 < 0.02**。
- 偏大（比如 > 0.05）说明上电时板子没水平静止放，或者焊接/轴向有问题。

**C. 若要用九轴，先验证磁力计轴向**
1. 丝印面水平缓慢转 360° → 磁力计 x/y 应画出**以原点为圆心的圆**（不偏心、不呈椭圆）。
2. 绕板子竖轴转 360° → Yaw **单调变化**、方向与转动一致、转完回到起点（误差 < 5°）。
3. 若方向**反了**或来回摆动，说明 `Fusion_Task` 里 `(-my, mx, mz)` 的符号/顺序与实物不符，
   在验证通过之前**不要开九轴**（Kp 虽已从 200 降到 1.5，但错误修正仍会污染 Yaw）。

**D. 若上电姿态不是「丝印面朝上平放」**
- 把 `icm42688_driver.h` 里的 `ACC_CALIB_REF_AXIS` 改成对应轴（0=X / 1=Y / 2=Z）。
- 程序会自动适应该轴朝上或朝下，但**必须让该轴竖直**、另两轴水平。

### 6.2 修掉一个上电顺序 bug

原来的上电流程里 **`fusion_ready = 1` 与开定时器发生在 `MahonyAHRSinit()` 之前**，

### 6.3 新增磁参考航向 H（轴映射验证工具）

诊断页在九轴下改为：

```
--- Mag / Heading ---
MX: +0.21
MY: -0.18
H : +137
```

`H` 是**用磁力计直接算出的参考航向**（倾角补偿后），每帧由 `Fusion_Task` 更新。
它和 Mahony 的 Yaw 用**完全相同的轴重映射 `(-my, mx, mz)`**，所以两者可以直接对比。

数值验证（主机端复刻该公式）：

| 绕竖轴转过 | H | 倾斜 20° 时的 H |
|---|---|---|
| −90° | −90.0° | −90.0° |
| −45° | −45.0° | −43.2° |
| 0° | 0.0° | 0.0° |
| +45° | +45.0° | +43.2° |
| +90° | +90.0° | +90.0° |

即 H 与转动 1:1，且倾斜补偿有效。

**怎么用它调**：

1. 板子水平放平，**长按**做一次磁力计硬铁校准（需要翻转设备，见 §4C）；
2. 绕**竖轴**慢慢转 360°；
3. 对照第 1 页的 Yaw：
   - H 单调、Yaw 也单调同向 → **映射正确**，可以进入 Kp 调参；
   - H 单调但 Yaw 反向/乱跳 → 重映射方向不对，把 `(-my, mx, mz)` 换成
     `(my, -mx, mz)` 或去掉负号再试；
   - H 显示 `noMag` 或不随转动变化 → 磁力计没读到有效值（I2C 或校准问题）。

### 6.4 九轴下 Yaw 的行为（调试时请留意）

- 九轴的 Yaw 是**绝对航向（相对磁北）**，所以上电会显示一个任意的初始角
  （比如 44°、137°），**这是正常的，不是误差**；
- 磁干扰源（喇叭、电机、金属桌面、手机）会让 Yaw 跳变或缓慢偏转；
  这属于硬铁/软铁问题，硬铁靠校准，软铁目前没做；
- 静止自动零偏修正（§2.11）在九轴下同样有效（会持续跟踪陀螺零偏），
  不会和磁力计打架。
### 6.5 踩坑记录：改了默认值但上电没变（Flash 优先）

**现象**：把默认改成九轴、重新编译烧录后，上电**仍然是六轴**。

**原因**：`Flash_Load_Settings()` 是**存储值优先**的：

```c
if (flag == FLASH_FLAG_VALUE_V2)   /* 存储有效 -> 用存储值 */
    *status = stored;              /* 默认分支根本不执行 */
else
    *status = 1;                   /* 只有 Flash 为空/版本不匹配才走这里 */
```

`FLASH_FLAG_VALUE_V2 = 0xA5A55A5A` 是在「默认六轴」那一版引入的。
板子当时已经烧过并运行过那一版，Flash 里存下了 `flag=0xA5A55A5A + status=0`。
之后只改默认值、不换 magic，读取时发现 magic 仍然匹配，就继续用存着的 `0` ——
**新默认值被旧存储完全盖住**。

**修正**：把 magic 换成 `0xA5A5C33C`，让旧存储失效，重新走默认分支。

> ⚠️ **这条要记住**：以后每次改「默认模式」这类行为，**必须同时换 magic**，
> 否则改了等于没改。magic 已挪到 `my_flash.h` 并附了演进历史（见文件内注释）。

**顺带加的防呆显示**：上电第 4 行现在显示 `模式 + 来源`：

| 显示 | 含义 |
|---|---|
| `9AX F` | 九轴，设置来自 Flash 的有效存储 |
| `9AX D` | 九轴，设置走了**默认值**（Flash 空/版本不匹配） |
| `6AX F` | 六轴，设置来自 Flash（你之前短按切过） |
| `6AX D` | 六轴，走了默认值 |

这样一眼就能区分「默认值生效了」还是「被 Flash 里的旧值盖住了」，
不用再靠猜。`Flash_Load_Settings()` 也新增了可选参数 `raw_flag` 来回传原始 magic。

**另注**：短按切换会**立刻把状态写回 Flash**，所以手动切换是持久化的。
换 magic 只会重置「默认值」，不会妨碍你之后按自己的意愿切换并保持。
### 6.6 航向约定：yaw = 0 指向哪里（已推严格推导 + 数值自检）

九轴跑通后（实测「转 90° → yaw 变 90°」，尺度与硬铁标定均正确），
把坐标系关系固定下来，以后不要再猜。

**由固件的轴重映射 `(-my, mx, mz)` 反推 MMC5603 的安装方向：**

| MMC 封装轴 | 指向板子坐标系 |
|---|---|
| `Xm` | 板子 **+Y** |
| `Ym` | 板子 **−X** |
| `Zm` | 板子 **+Z** |

镜像检验：`Xm × Ym = (0,0,1) = Zm` → **保持右手系，是纯旋转（绕 Z 转 +90°），不是镜像**。
所以那个 90° 重映射是对的，代码里的 `(-my, mx, mz)` 不用动。

**于是：**

| 问题 | 答案 |
|---|---|
| `yaw = 0` 指向哪 | 板子的 **+X 轴** 指向**磁北** |
| yaw 增大的旋向 | 板子**顺时针**转（从板子上方向下看），即罗盘航向增加 |
| 自检 | 板子绕竖轴顺时针 90° → yaw 读 **+90°**（与实测一致 ✅） |

**注意标的是【磁北】不是【真北】**，差一个磁偏角（当地磁偏角，中国境内约 −1°～−11°）。
如果需要真北航向，加一句：

```c
yaw_true = yaw_mahony + MAG_DECLINATION_DEG;   /* 当地磁偏角, 东偏为正 */
```

**怎么快速找到磁北**：板子放平，慢慢转，**yaw 读数变成 0°** 时，
板子的 **+X 那条边**就指向磁北。

**一个可选的显示改进**（没做，按需再说）：OLED 第 1 页显示 8 向罗盘
（`N / NE / E / SE / S / SW / W / NW`），比看数字直观得多，
答辩演示也更好看。加这个大约 20 行代码。
### 6.7 航向旋向修正 + 零点标定（已完成）

**实测确认的现象**：板子顺时针慢转时 `icm42688_gyro_z` 读**负数**。
这说明陀螺 Z 的符号与标准罗盘相反，而且磁力计也一致地反着
（这就是九轴仍能稳定锁定的原因）。原来的表现是「顺时针减小、逆时针增大」。

**修正方式：陀螺与磁力计必须【成对】翻号。**

只翻磁力计会让两者旋向相反、误差项无法抵消，yaw 会震荡或被拉飞。所以用宏统一控制：

```c
#define HEADING_STD_CONVENTION   1     /* 1=顺时针增大(标准罗盘)  0=旧约定 */
```

| `HEADING_STD_CONVENTION` | 陀螺 Z | 磁力计重映射 | 旋向 |
|---|---|---|---|
| `1`（当前） | `-gyro_z` | `(+my, -mx, mz)` | 顺时针增大 ✅ |
| `0`（旧） | `+gyro_z` | `(-my, +mx, mz)` | 顺时针减小 |

同步修改的四处（都已用宏包住，不会漏改）：
`Fusion_Task` 九轴分支、`Fusion_Task` 六轴分支、
上电 `MahonyAHRSinit` 实参、诊断页参考航向 `H`。

**修正结果（实测）**：顺时针**增大**、逆时针**减小** ✅ 符合标准罗盘。

#### 零点偏移（90° 安装角导致，无法用符号消除）

穷举全部 8 种符号组合的结论：

| 组合 | 顺时针 | yaw=0 指北 | 陀螺/磁力计自洽 |
|---|---|---|---|
| `(-my, +mx)` 原来 | 减小 | ✗ | ✅ |
| `(+my, -mx)` 现在 | **增大** | ✗ | ✅ |
| `(mx, my)` | 增大 | ✅ | ❌ 打架 |

因为 MMC5603 的 XY 相对板子差 90°（否则不需要重映射），而 yaw 公式
`atan2(-by, bx)` 是写死的，所以**「旋向正确」与「零点在正北」不能同时满足**。
选择了旋向正确 + 自洽，零点用常量偏移补：

```c
#define HEADING_ZERO_DEG       179.0f
```

**标定方法**：板子放平指向你认定的磁北，读出当时的 yaw，**取相反数**填进去。
（实测指向磁北时显示 −179，所以填 +179。）

显示时用 `Wrap180()` 归一化到 (−180, +180]；只影响显示，不影响融合内部角度。

> 若之后发现刻意调得不准，改 `HEADING_ZERO_DEG` 即可，不需要动融合代码。
### 6.8 上电稳定时间与显示刷新率优化

**问题**：每次上电要等一会儿才稳定；屏幕刷新偏慢、肉眼可见跳字。

**根因（两部分，都定位到了）**：

1. **上电总耗时 2.11 秒**，其中 `IMU_Calibrate()` 占 1.0 秒（500 样本 × 2ms，
   这是静置校准时序，不能压缩，否则零偏估计噪声变大），状态提示占 0.8 秒。
2. **静止自动零偏（auto-zero）首次学习要 5 秒** —— 这是"要等一会儿"的主因。
   原来固定 50 个样本 × 100ms = 5.0 秒才做第一次修正，
   在此之前陀螺残余零偏（实测 0.113 dps ≈ 6.8°/分钟）一直在让 Yaw 漂。
3. 显示刷新：主循环一轮约 12ms，阈值 10 → 只有约 **8 Hz**。

**改动**：

| 项 | 改前 | 改后 | 说明 |
|---|---|---|---|
| 显示刷新阈值 | `>= 10`（约 8 Hz） | **`>= 4`（约 20 Hz）** | 流畅多了 |
| 上电稳定延时 | 100 ms | **50 ms** | 实测足够 |
| 状态提示停留 | 800 ms | **400 ms** | 仍看得清 |
| auto-zero 首学阈值 | 固定 50 样本（5 s） | **首次 10 样本（1 s）**，之后 50 样本 | 关键改动 |

**auto-zero 两档阈值的理由**：

- **首次只要 10 个样本（静止 1 秒）**就修正，让开机头几秒的漂移尽快消失。
  样本少，噪声约 `0.028/√10 = 0.009 dps` —— 比原来的 0.11 dps 残余零偏
  小一个数量级，而且**之后会自动精修**。
- **之后回到 50 个样本（5 秒）**，长期跟踪更稳、不易被扰动带偏。

**效果**：

| 指标 | 改前 | 改后 |
|---|---|---|
| 上电到可用 | 2.11 s | **1.66 s** |
| 零偏首学 | 5.0 s | **1.0 s** |
| Yaw 稳定所需 | 约 5 s | **约 1 s** |
| 显示刷新率 | 约 8 Hz | **约 20 Hz** |

**若还想更快刷新**：瓶颈是 `MMC5603_ReadData_Single()` 里的 10 ms 阻塞延时
（它在每次主循环都被调用）。要突破 20 Hz 需要把磁力计改成**连续模式 + 非阻塞读取**
（或缩短那个延时到 7~8 ms，但要先确认测量确实完成）。这是一次独立改造，按需再做。
### 6.9 上电收敛慢的根治（三段式）

**问题**：上电后 Yaw 要等一会儿才收敛到稳定值。

**仿真定量**（按固件真实参数：200Hz、初值误差 90°、收敛到 ±1° 所需时间）：

| twoKp | 时间常数 | 收敛时间 |
|---|---|---|
| 0.5 | 2.00 s | 8.98 s |
| 1.0 | 1.00 s | 4.49 s |
| **2.0（改前）** | 0.50 s | **2.23 s** |
| 3.0 | 0.33 s | 1.49 s |
| **6.0（收敛期）** | 0.17 s | **0.74 s** |
| 15.0 | 0.07 s | 0.29 s |

所以 `twoKp = 2.0` 确实要 2.2 秒，加上初值本身的采样噪声，观感就是"收敛很慢"。

**两个根因，分别解决**：

**① 初值本身不准**（初值误差要全靠融合收敛掉）
原来只取 **1 次**测量就调 `MahonyAHRSinit`，磁力计单次噪声直接变成初值航向误差。
改为 **3 次磁力计 + 5 次加速度计取平均**：磁力计单次噪声约 1 mG，
3 次平均降到约 0.58 mG，航向噪声从约 0.2° 降到约 0.1°。
代价：磁力计每次读取内部有 10 ms 延时，3 次约 30 ms，可接受。

**② 收敛增益偏低**
新增**收敛期大增益**机制：

```c
#define MAHONY_TWOKP_9AXIS        2.0f   /* 稳态: 抗磁干扰优先 */
#define MAHONY_TWOKP_9AXIS_BOOT   6.0f   /* 收敛期: 快速收敛 */
```

`GyroAutoZero_Task` 维护一个 `heading_settling` 标志：
**判定为静止** 且 **首次零偏还没学完**（约 1 秒）时为 1，
`Fusion_Task` 在此时把增益切到 `6.0`，学完之后自动切回 `2.0`。

**为什么这样安全**：
- 大增益**只在静止段生效** —— 磁干扰通常伴随运动，静止时磁场相对干净；
- 一旦检测到运动（陀螺或加速度超阈值）立刻清 `heading_settling`，
  不会在运动中被磁干扰拽走；
- 只持续约 1 秒，之后长期仍是 `2.0`，**抗磁干扰能力不受影响**；
- 用 `Mahony_SetKp()` 而不是重新 `Mahony_Init()` —— 后者会重置四元数与积分项。

**效果**：

| 指标 | 改前 | 改后 |
|---|---|---|
| 初值航向误差 | 单次采样噪声（约 0.2°） | 3 次平均（约 0.1°） |
| 收敛期增益 | 2.0（恒定） | 6.0 → 稳定后 2.0 |
| 收敛到稳定 | 约 2.2 s | **约 0.8 s** |
| 长期抗磁干扰 | — | 不变 |

**若还想更快**：把 `MAHONY_TWOKP_9AXIS_BOOT` 提到 10~15（0.3 秒收敛），
但增益越高、静止期的磁噪声越容易被跟随，可能出现读数轻微抖动。
