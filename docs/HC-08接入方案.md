# HC-08（BLE 4.0 串口透传）接入方案

> 本文回答三件事：**怎么接线**、**固件里已经配了什么**、**怎么一步步验证**。
> 真源：`Core/Src/usart.c`（USART2）、`Core/Src/gpio.c`（STATE 脚）、
> `MDK-ARM/icode/driver/hc08.c`（驱动）、`MDK-ARM/icode/task/ble_task.c`（任务）、
> `Core/Src/main.c`（接收回调分发）。

---

## 0. 速览

| 项 | 值 |
|---|---|
| 串口 | **USART2**：PA2 = TX（→ 模块 RXD）、PA3 = RX（← 模块 TXD） |
| 参数 | **9600 8N1**，无流控（HC-08 出厂默认，与固件一致） |
| 接收方式 | 空闲中断 + 中断接收（`HAL_UARTEx_ReceiveToIdle_IT`），**不用 DMA**（BLE 速率 ≤960 B/s，中断足够；DMA1_CH6 现已空闲） |
| 连接状态 | **PB15** 读模块 STATE 脚（可选接线，下拉输入） |
| 固件任务 | `ble_task`（优先级 Normal，栈 192 word），驱动 `hc08.c` |
| 屏幕 | `oled_task.c` 的 `OLED_SCREEN_SEL = OLED_SCREEN_HC08(3)`，两页，上/下键翻页 |

## 1. 模块事实（先看这条，别把模块烧了）

1. **供电 3.3 V（2.0~3.6 V）** —— ⚠ **不能接 5 V**。
   这一条与 **GPS 底板正好相反**（DX-GP22-A 底板要 3.6~6 V，典型 5 V）。
   接之前务必看一眼模块丝印：常规 HC-08 标 `VCC 3.3V`；只有明确标了 3.6~6 V 的板子才自带 LDO。
2. **逻辑电平 3.3 V**，与 STM32 直连，无需电平转换。
3. **默认串口 9600 8N1**，与本工程 USART2 配置一致 —— 意味着"接上就能通"，不用先改任何配置。
4. **透传模型**：模块把 BLE 收到的字节原样从 TXD 吐出；把 RXD 收到的字节原样发给手机。
   也就是说，手机和 MCU 之间就是一根"无线的串口线"。
5. **AT 指令**在**未连接**状态下从串口直接发（见 §5）；一旦手机连上，模块进入透传、通常不再解析 AT。
6. **STATE 脚**：与手机建立连接后输出高电平，断开后回低 —— 用它就能在屏幕上显示"手机连没连上"。
7. ⚠ **HC-08 是 CC2541 + 汇承私有透传固件，不是标准 BLE 串口 GATT 服务**：
   - 官方"汇承"App、以及通用 BLE 调试 App（nRF Connect / BLE 串口助手）都能连；
   - **自研 App** 需要先用 nRF Connect 查出该模块的服务/特征 UUID，再按它写代码
     （比标准模块多一步，但可行）；
   - 若后续明确要做通用自研 App，换 **JDY-31 / AT-09 / HM-10** 这类标准 GATT 模块会更省事。
     这一取舍建议写进论文的"方案对比"里。

## 2. 接线（照着接）

| HC-08 引脚 | 接到节点 B | 说明 |
|---|---|---|
| **VCC** | **3.3 V** | ⚠ 见 §1 第 1 条：**不是 5 V** |
| **GND** | **GND** | 必须共地，否则串口乱码/收不到 |
| **TXD** | **PA3**（USART2_RX） | 模块发 → 单片机收 |
| **RXD** | **PA2**（USART2_TX） | 单片机发 → 模块收 |
| **STATE**（可选，推荐） | **PB15** | 已连接 = 高电平；不接也能通信，只是屏幕一直显示 `NOT CONN` |
| KEY / EN（若有） | 不接（悬空） | AT 指令在未连接状态下直接走串口，不需要拉这个脚 |

```
       节点 B（STM32F103C8T6）                    HC-08
   ┌───────────────────────────┐            ┌──────────────┐
   │  PA2 (USART2_TX) ─────────┼───────────►│ RXD          │
   │  PA3 (USART2_RX) ◄────────┼────────────│ TXD          │
   │  PB15 (HC08_STATE) ◄──────┼────────────│ STATE (可选) │
   │  3.3V ────────────────────┼───────────►│ VCC          │
   │  GND ─────────────────────┼───────────►│ GND          │
   └───────────────────────────┘            └──────────────┘
        ⚠ VCC 必须 3.3 V；TXD/RXD 是交叉连接（不是同名对接）
```

**接线检查三件事**：① 是 3.3 V 不是 5 V；② TXD↔PA3、RXD↔PA2（交叉）；③ 共地。

## 3. 手机上装什么

| 目的 | 用什么 |
|---|---|
| 快速验证"模块活着、能连" | 手机蓝牙设置里应能看到名为 `HC-08`（或改名后的名字）的设备 |
| 收发数据（联调主力） | 官方"**汇承**"App，或通用 BLE 调试 App（**nRF Connect**、**BLE 串口助手**） |
| 自研 App（后续） | 先用 nRF Connect 连上，记下 Service / Characteristic UUID（含 notify 与 write），再写代码 |

连接后应立刻收到固件上电发的 BOOT 报文（见 §6）。

## 4. 固件侧已经配好的东西

| 位置 | 内容 |
|---|---|
| `Core/Src/usart.c` | `MX_USART2_UART_Init()`：**9600 8N1**、`UART_MODE_TX_RX`、无流控；`HAL_UART_MspInit()` 里配 **PA2=AF_PP / PA3=INPUT**，并使能 **USART2_IRQn（优先级 5,0）** |
| `Core/Src/gpio.c` | `HC08_STATE_Pin`（PB15）配为**下拉输入**：不接线时恒读 0（= 未连接），不会悬空乱跳 |
| `Core/Inc/main.h` | `HC08_STATE_Pin` / `HC08_STATE_GPIO_Port` 宏 |
| `Core/Src/main.c` | `HAL_UARTEx_RxEventCallback()` 里新增 **USART2 → `HC08_RxEventCallback()`** 分支（USART1→GPS、USART3→IMU 保持不变） |
| `icode/driver/hc08.c/.h` | 驱动：空闲中断接收 + 环形缓冲 + 按行切分 + 发送 + AT 计数 + STATE 读取 |
| `icode/task/ble_task.c/.h` | 任务：上电 AT 探测、发 BOOT 报文、发送单槽暂存报文（`BLE_Report()`）、解析手机命令、可选回显 |
| `Security Watch.ioc` | 新增 `PB15 = HC08_STATE`（GPIO_Input, PULLDOWN），`Mcu.PinsNb` 同步 34→35 |
| `Security Watch.uvprojx` | 新增 `hc08.c/.h` 编译条目（81 个文件） |

**`ble_task.c` 顶部的四个开关**（首次联调建议按默认值）：

| 宏 | 默认 | 作用 |
|---|---|---|
| `BLE_SEND_AT_PROBE` | **1** | 上电发 `AT`，模块回 `OK` → 屏幕 `ATOK` 计数 +1，**这是"串口链路通不通"的判据** |
| `BLE_SET_NAME` | 0 | 改名（`AT+NAMEJBX-01`）。会写入模块配置，**确认链路通了再开** |
| `BLE_SEND_BOOT_MSG` | 1 | 上电发 `{"dev":"JBX-01","ev":"BOOT"}`，手机 App 里立刻能看到 |
| `BLE_ECHO_RX` | 1 | 把手机发来的每一行回显给手机（联调验证双向；量产可关） |

## 5. AT 指令速查（**未连接**状态下用；每条末尾必须带回车换行）

| 指令 | 作用 | 典型应答 |
|---|---|---|
| `AT` | 测试链路 | `OK` |
| `AT+RST` | 软复位 | `OK+RST` / `OK` |
| `AT+NAME<名称>` | 改蓝牙名（≤12 字符，不要带空格） | `OK+Set:<名称>` |
| `AT+BAUD<n>` | 改波特率：1=1200 2=2400 3=4800 **4=9600** 5=19200 6=38400 7=57600 8=115200 | `OK+Set:n` |
| `AT+ADDR` | 查 MAC | `OK+ADDR:xxxxxxxxxxxx` |
| `AT+RFPM<n>` | 发射功率档位 | `OK+Set:n` |

⚠ 三条纪律：
1. **不同批次 HC-08 固件的指令集略有差异** —— 拿不准的指令不要发，以模块手册为准；
2. **改了波特率必须同步改 `usart.c` 的 `huart2.Init.BaudRate`**，否则两边对不上、全线乱码；
3. 改名前先确认 `AT` 能回 `OK`（链路先通再改配置），改错了要接 PC 才能恢复。

在 PC 上做这些最方便：USB-TTL 接模块（TXD↔RXD 交叉、共地、VCC=3.3 V），
sscom 开 9600 8N1，勾上"发送新行"，逐条发。

## 6. 通信协议（一行一条，`\r\n` 结尾）

**设备 → 手机**（固件目前会发这三种）：

| 报文 | 触发 | 示例 |
|---|---|---|
| BOOT | 上电 | `{"dev":"JBX-01","ev":"BOOT"}` |
| STAT 应答 | 手机发 `STAT` | `{"ev":"STAT","gps":{"v":1,"lat":301875525,"lon":1208166950,...}}` |
| PONG | 手机发 `PING` | `{"ev":"PONG"}` |
| **告警报文** | 跌倒确认后由告警任务调 `BLE_Report()` 投递 | 见下 |

告警报文（课题要求 4 的核心数据，约 230 字节）：

```json
{"t":1712345678,"dev":"JBX-01","ev":"FALL","conf":93,
 "acc":[1200,-2800,3900],"rpy":[821,-153,76],"step":98,"seq":4521,
 "gps":{"v":1,"lat":301875525,"lon":1208166950,"q":1,"sat":11,
        "hdop":290,"alt":1200,"spd":0,"cog":0,"fix_age":0}}
```

- 标度（全部定点整数）：`t` = Unix 秒；`conf` = 百分比；
  `acc` = mg；`rpy` = 0.1°；`gps.lat/lon` = 度×1e7；`alt` = cm；`spd` = cm/s；
  `cog` = 0.01°；`fix_age` = ms（**室内无星时 `v=0`，但 `fix_age` 会告诉云端最后已知位置有多旧，不能丢**）。
- 发送接口：`BLE_Report(json)`（非阻塞，单槽暂存；槽忙或报文过长会记进 `BLE_GetStats()` 的 drop 计数）。

**手机 → 设备**（`ble_task` 解析）：

| 命令 | 作用 |
|---|---|
| `PING` | 回 `{"ev":"PONG"}`（验证上行链路） |
| `STAT` | 回一条带 GPS 快照的状态报文（验证下行 + 定位数据） |
| `AT...` | 转发给模块（仅在**未连接**时有效，台架调试用） |
| 其它 | 忽略（留作后续协议扩展） |

## 7. 验证分级

| 级别 | 做什么 | 通过标准 |
|---|---|---|
| **L0 台架（不用 MCU）** | USB-TTL + sscom，3.3 V 供电，9600 8N1 发 `AT` | 模块回 `OK`；手机能搜到 `HC-08` 并能连上 |
| **L1 上板串口链路** | 接好 5 根线（VCC/GND/TXD/RXD[/STATE]），烧固件，看 OLED 的 HC-08 屏 | `AT` 计数 ≥1 且 **`ATOK` ≥1**（模块回 OK）；`TXB` 在涨；手机里看到 `BOOT` 报文 |
| **L2 连接状态** | 手机连上/断开模块 | 屏幕 `LINK` 在 `CONN`/`NOT CONN` 之间变化（需接 STATE 脚） |
| **L3 双向** | 手机发 `PING` → 应收 `PONG`；发 `STAT` → 应回 GPS 状态 | 回显与应答都正确 |
| **L4 端到端** | 触发一次跌倒告警（或直接调用 `BLE_Report()` 发测试报文） | 手机收到完整告警报文，字段齐全、`gps` 片段与屏幕第 3 页一致 |

**OLED 的 HC-08 屏（上/下键翻页）**

```
【1/2 链路】                【2/2 统计】
HC-08 BLE        1/2        HC-08 STAT       2/2
LINK  NOT CONN              RXB    00000000
TXB   00000000              ATOK   0000
AT    0000   ATOK 000       ATERR  0000
LAST RX LINE                OVR    0000
OK                          SEND   0000
UP/DN=PAGE 1/2              DROP   0000
```

| 字段 | 含义 | 正常 |
|---|---|---|
| `LINK` | STATE 脚电平：手机已连接 / 未连接 | 手机连上变 `CONN` |
| `TXB` / `RXB` | 累计发出/收到字节数 | `TXB` 上电后应 ≥ 30（AT + BOOT 报文） |
| `AT` / `ATOK` / `ATERR` | 发出的 AT 条数 / 收到 `OK` 次数 / 收到 `ERROR`·`FAIL` 次数 | `ATOK ≥ 1` = 串口链路通 |
| `LAST RX LINE` | 最近收到的一行（模块应答或手机命令） | 上电后应显示 `OK` |
| `OVR` | 接收环形缓冲溢出丢字节次数 | 0 |
| `SEND` / `DROP` | 成功发出的帧数 / 被丢弃的帧数 | `DROP` 长期为 0 |

## 8. 排查表

| 现象 | 最可能的原因 | 先做什么 |
|---|---|---|
| `ATOK` 一直是 0，`LAST RX LINE` 空 | 接线/供电问题 | 查 ①**VCC 是不是 3.3 V**（接 5 V 可能已损坏）②TXD/RXD 是否交叉（模块 TXD→**PA3**）③共地 ④模块上电后指示灯是否闪 |
| `AT` 计数在涨但 `ATOK` 不涨 | 收到的是乱码 → 波特率不对 | 模块可能被改过波特率：接 PC 用 sscom 逐档试（9600 优先），或发 `AT+BAUD4` 改回 9600 |
| `ATOK ≥1` 但手机里收不到 `BOOT` | 手机没连上 / 连错设备 | 确认手机连的是本模块（名字 `HC-08` 或改后的名字）；`LINK` 是否 `CONN` |
| `LINK` 一直 `NOT CONN` 但手机显示已连接 | STATE 脚没接或接错 | 不接也能用（只是没这个指示）；接了要确认接的是 **PB15** 且模块 STATE 有输出 |
| 手机收到的中文/JSON 乱码 | 波特率不匹配或 App 显示编码问题 | 先确认 `ATOK` 正常；App 侧按 ASCII/UTF-8 显示 |
| `DROP` 在涨 | 报文过长（>256 B）或上一帧还没发完 | 看告警报文长度；必要时缩短 JSON 或放慢上报 |
| 手机断开后再也收不到 | 模块未自动恢复 | 复位模块（重新上电或 `AT+RST`）后观察；必要时在 `ble_task` 里加"长时间无数据则重装接收" |

## 9. 与其它模块的关系 / 论文素材

- **串口独占**：USART2 只给 HC-08；USART1=GPS、USART3=DIY IMU，三者互不干扰
  （`main.c` 的 `HAL_UARTEx_RxEventCallback` 按 `huart->Instance` 分发）。
- **USART2 用中断而不是 DMA**：最初是因为 DMA1_CH6 被 WS2812 的 TIM 占用；
  2026-10-14 删除 ws2812b 后 CH6 已空闲，但 BLE 速率 ≤ 960 B/s，中断方式更简单，故保持不变
  （这是"资源受限下如何分配外设"的一个小例子，可写进论文）。
- **BLE 不看连接状态也敢发**：没有 STATE 脚时无从判断手机是否连着，而未连接时数据只是"进空气"，
  不造成危害；因此发送逻辑不依赖连接状态（接了 STATE 脚则只用于显示）。
- **可靠性取舍**：告警是低频事件（20 s 确认窗口 + 120 s 冷却），故用**单槽暂存 + 丢弃计数**
  而不是多槽队列 —— 省 RAM，且丢帧可观测。
- **静态 RAM 账**：接入 HC-08 后静态 RAM 一度只剩 240 B，因此把
  `configTOTAL_HEAP_SIZE` 9280 → **8192**（堆实测只需约 6.9 KB，仍余 2 KB），
  静态 RAM 余量回到约 1.3 KB。`ws2812b` 驱动（无调用者）已移出工程并删除源码。
