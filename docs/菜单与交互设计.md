# 菜单与交互设计（节点 B）

> 目标：把现在"一屏到底"的调试界面升级为**可操作的四页菜单**，让设备在无手机、无上位机时也能查看状态与改设置。
> 前置条件（已完成）：按键驱动（消抖/连发/长按 + 导航锁存 `Key_TakeNav`）、OLED 多屏与翻页、GPS 三页数据、HC-08 两页数据。
> 真源：`MDK-ARM/icode/task/{menu,oled,alarm}_task.c`、`driver/key.c`、`driver/beep.c`

---

## 1. 设计要点（先看这 3 条，都是踩过坑的）

### 1.1 事件归属：**队列只能有一个消费者**

`key.c` 的事件队列是"单生产者（`Key_Scan` 在 `alarm_task`，10 ms）× 单消费者"。
现在有两处想拿事件：

- `alarm_task`：长按"返回" → 取消告警；
- `menu_task`：上/下翻页、OK 进入、返回退出。

**不能两个任务都调 `Key_GetEvent()`**（会互相抢事件、菜单跳页）。
推荐的归属规则（本设计采用）：

| 事件 | 归属 | 说明 |
|---|---|---|
| 上/下（含连发） | 菜单（用 `Key_TakeNav()` 锁存，**不占队列**） | 已在 GPS/HC-08 页用过，天然不冲突 |
| OK | 菜单（`Key_GetEvent()`） | 菜单是队列的**唯一消费者** |
| 返回（短按） | 菜单 | 退出当前页/返回上级 |
| **返回（长按，`B-LNG`）** | **告警优先** | 处于 `PENDING` 时代表"取消告警"；否则才归菜单 |

实现方式：`alarm_task` 继续用 `Key_PeekEvent()`（只"看"不"取"）判断 `B-LNG`；
**当且仅当**当前不是 `PENDING` 时，菜单才把 `B-LNG` 当作"退出"。
这样队列消费者始终只有 `menu_task` 一个，语义冲突由"告警优先"规则消解。

### 1.2 谁刷屏：**OLED 只归 `oled_task`**

`OLED.c` 是**软件 I2C**，一次整屏刷新耗时可观。任何其它任务都不要直接刷屏
（`imu_recv_task`、`gps_task` 都遵守这条），菜单只负责"**决定显示什么**"，
真正的绘制留在 `oled_task`：

```
menu_task  ──写──>  菜单状态（当前页/光标/设置项）  ──读──>  oled_task 绘制
alarm_task ──写──>  告警状态                        ──读──>  oled_task 绘制
```

用一个小结构体 `Menu_View_t`（当前页、光标行、是否在编辑、各设置项值）传递，
`oled_task` 每 100 ms 取一次快照绘制。

### 1.3 告警优先：`PENDING` 时菜单让位

跌倒进入 `PENDING` 的 20 s 窗口内，屏幕应显示**告警页**（大字提示 + 倒计时 + "长按返回取消"），
而不是菜单。规则：

```
if (告警状态 != IDLE)  显示告警页（并忽略菜单翻页）
else                   显示菜单页
```

## 2. 页面结构（4 页，每页最多 8 行 × 21 字符）

| 页 | 标题 | 内容 | 可操作 |
|---|---|---|---|
| **1 主页** | `FALL DETECT` | 设备名/ID、链路状态（节点A帧率、GPS 定位、BLE 连接）、电池（暂无 ADC 预留）、当前时间 | 无（纯状态） |
| **2 状态** | `STATUS` | 子页滚动：节点A链路（帧率/丢帧/CRC）、GPS（FIX/Q/ST/VW/MX/lat/lon）、BLE（LINK/TXB/RXB/SEND/DROP）、系统（HEAP/运行时长/各任务栈余量） | 上/下翻页 |
| **3 设置** | `SETTINGS` | 可改项列表（见下），光标行反显 | ↑↓ 移动、OK 进入编辑、↑↓ 改值、OK 确认、返回取消 |
| **4 校准** | `CALIB` | 条目：MMA（加速度零偏）、陀螺零偏、磁力计 8 字校准、恢复出厂、保存到 Flash | OK 执行，返回退出 |

**设置项（第 3 页）**，按"演示时真会用到"排序：

| 项 | 取值 | 作用 |
|---|---|---|
| `Fall Sens` | 低/中/高 | 跌倒判定阈值（映射到置信度阈值，最影响误报/漏报） |
| `Beep` | 开/关 | 蜂鸣器总开关 |
| `Confirm Win` | 10/20/30 s | 告警确认窗口 |
| `Dev ID` | 文本（数字/字母） | 报文的 `dev` 字段（也用于 BLE 名） |
| `Screen` | IMU/GPS/BLE/STAT | 无操作时默认回到哪个页面（替代现在改宏重烧） |

> ⚠ `Screen` 这一项很有价值：现在切屏要改 `OLED_SCREEN_SEL` 重新编译，
> 做进设置后**一个固件就能在现场切换所有界面**，答辩演示会顺很多。

## 3. 交互状态机

```
        ┌──────────────────────────────────────────────┐
        │                 MENU_RUN                     │
        │  页内浏览：↑↓ 移动光标 / 翻子页               │
        └───┬───────────────┬──────────────┬───────────┘
     OK │            BACK │         B-LNG│(长按返回)
        ▼                 ▼              ▼
  ┌───────────┐    ┌───────────┐   ┌──────────────────┐
  │ MENU_EDIT │    │ 返回上级  │   │ 若 PENDING → 取消 │
  │ 编辑当前项│    │ 或回主页  │   │ 否则 → 回主页     │
  └─────┬─────┘    └───────────┘   └──────────────────┘
     OK │ (确认并写回)      BACK │ (取消, 恢复原值)
        ▼                       ▼
      MENU_RUN                MENU_RUN
```

- **按键去抖与连发**已在 `key.c` 内完成，菜单只处理"事件"，不处理电平；
- **长按 OK** 可留作快捷操作（例如"立即进入设置"），首版不做。

## 4. 任务、优先级与栈

| 项 | 取值 | 说明 |
|---|---|---|
| 任务 | `menu_task` | 与 `oled_task` 合并亦可（见 §6 步骤 1），但**逻辑上独立** |
| 优先级 | `osPriorityBelowNormal` | 低于 IMU/TinyML/告警，高于 OLED 绘制 |
| 栈 | **192 word（768 B）** | 只做状态机与少量整数运算；字符串拼接一律用 file-static 缓冲 |
| 周期 | 20 ms | 按键响应 ≤20 ms，肉眼无感；与 `Key_Scan` 的 10 ms 节拍匹配 |
| 堆 | 192×4 = 768 B | 当前堆余量约 2 KB，够；见 `tools/heap_ledger.py` |

**RAM 预算**：菜单状态结构（页号/光标/设置项值 + 副本）约 40 B，全是静态；
设置项若要存 Flash，需要 `my_flash` 风格的读写（节点B 目前未用 Flash 存参数，首版可只存 RAM，
掉电丢失 —— 演示够用，写进"后续工作"）。

## 5. 实现步骤（每步都能单独编译上板验证）

| 步 | 做什么 | 验证方式 |
|---|---|---|
| **1** | 加 `menu_task`（骨架 + 状态结构），`oled_task` 增加 `OLED_SCREEN_MENU` 屏：只画**主页**（静态字段 + 已有的链路数据） | 上电看到主页，字段数值与 GPS/BLE 页一致 |
| **2** | 接入导航：↑↓ 在主页/状态页之间切换（复用 `Key_TakeNav()`），状态页做成子页滚动 | 按键翻页正常，不跳页、不重复 |
| **3** | 加**设置页**与 `MENU_EDIT` 状态机（先做 3 项：Fall Sens / Beep / Confirm Win），改动先只作用于 RAM | OK 进入编辑、改值、确认；蜂鸣器开关立刻生效可听见 |
| **4** | 与告警联动：`PENDING` 时强制显示告警页并让出按键；`B-LNG` 告警优先 | 触发一次告警（可临时用调试按键模拟），确认菜单不会抢走取消操作 |

## 6. 与其它模块的关系

- **告警状态机**（下一步主线）：`alarm_task` 持有 `IDLE/PENDING/CONFIRMED/CANCELLED`，
  菜单只**读**它来决定显示哪一页；
- **GPS / HC-08 / IMU**：菜单只读它们的快照接口（`GPS_GetFix()`、`HC08_*`、`IMU_Recv_GetSnapshot()`），
  与"三套调试屏"用的是同一批数据，因此菜单页的数值天然与调试页一致；
- **BLE**：设置项改动后可通过 `BLE_Report()` 回一条确认（可选），手机端就知道参数变了；
- **误报样本**：`CANCELLED` 事件应落盘/计数（论文里"误报率"的数据来源），建议在告警状态机里做。

## 7. 风险与取舍

| 风险 | 处理 |
|---|---|
| 菜单与告警抢按键 | §1.1 的"队列唯一消费者 + 告警优先"规则；上/下走 `Key_TakeNav()` 锁存天然不冲突 |
| 软件 I2C 刷屏慢 | 菜单不直接刷屏；`oled_task` 统一 100 ms 刷新 |
| 设置项存 Flash 掉电保存 | 首版只存 RAM（够演示），写进"后续工作"；如需保存，参考节点A 的 `my_flash` |
| 菜单代码把 `oled_task` 撑大 | 菜单绘制独立函数 + `#if` 包住，避免影响 IMU/GPS/BLE 三套调试屏的编译 |
| 栈溢出 | 所有字符串/缓冲用 file-static；`menu_task` 栈 768 B 且只做整数运算 |
